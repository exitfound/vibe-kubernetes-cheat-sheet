## Контекст

`scheme/` вырос до 108 карточек (cluster 21, workloads 19, network 37, storage 31).
Каждая новая писалась вручную: геометрия литералами, `build()` императивно, `enter()`
с ручной арифметикой задержек. Замеры по 21 карточке cluster (6 879 строк):

|---|---|
| Строк в шапках геометрии | 1 294 (18%), 811 литеральных чисел |
| `class Scene` + `build()` + `reset()` | 1 882 (27%) |
| Скопированные `resetStep(s)` | 21 из 21, идентичны |

| Блок фиолетового Pod с захардкоженным `#c0b0ff` | 12 карточек, 26 литералов |

Проблема не в объёме, а в том, что **повторяющийся нарратив не выражен как повторяющийся**:
хореография «пакет летит A→B, по прилёту загорается B» написана руками 86 раз.

**Цель.** Карточка описывается данными, повторы живут в `lib/`, правила имеют одно место
жительства и машинную проверку, а проверки перестают быть регекспами по тексту и становятся
утверждениями об импортированных данных. **Визуально анимация не меняется** - это инвариант.

**Область.** Изначально только `cluster` (21 карточка) + общий `lib/`. Остальные три категории
идут по плейбуку из части IV. **workloads (19) закрыта, см. часть V; осталось network и storage.**

## Модель исполнения: каждый пункт - отдельный сабагент

Я нарезаю задание, проверяю результат и при провале отправляю НОВОГО сабагента с конкретной
находкой. Старый уже держит в контексте свою неверную модель происходящего.

### Правила нарезки, выведенные опытом

- **Никаких двух сабагентов на один файл.** Миграция карточек параллельна по построению
  (карточка = файл), но правка `<cat>-kit.js`, `scene-spec.js` или `step-spec.js`
  **сериализуется через меня**. Требуется рост DSL - сабагент останавливается и докладывает.
- **Ломать надо изолированную копию `scheme/`**, поданную на своём порту, а не живое дерево.
  Это придумал сабагент, а не я, и оказался прав: параллельные мутации дают друг другу
  ложные красные. Стало правилом со второго батча.
- **Пилотные карточки - строго по одной.** Параллелить их значит повторить одну ошибку
  четыре раза.
- Основная масса - батчами по 3-4, у каждого агента **своя** карточка для поломок.

### Что получает сабагент

1. Путь к этому файлу и номер пункта.
2. Точную область: что можно трогать, что нельзя.
3. Критерий приёмки **цифрой**, а не словами.
4. Требование **доказать, что тест умеет падать**: точечная поломка, красный прогон,
   восстановление, `cmp`. Утверждение, которое не уронили, считается непроверенным.
5. Требование отдать отрендеренные кадры, а не вывод о них.

### Что не делегируется

- Читаю `git diff` целиком.
- Сам запускаю `npm test` и `oracle:diff`, не верю отчёту.
- **Сам смотрю на кадры.** Проход, отчитавшийся «35 диаграмм, ноль находок в линте», открыл
  6 кадров из 35 и внёс три дефекта, которых не видело ни одно правило. Ремонт внёс четвёртый.
- Отчёт сабагента - заявка, а не факт. **За этот рефакторинг проверка опровергла заявку
  или мою собственную запись семь раз** (список в части III).

### 3.8 Две правки после приёмки, обе - исправление МОИХ решений

**1. Грамматика геометрии именуется по категории.** Мой критерий приёмки требовал шесть
одинаково названных имён во всех четырёх китах, и это протащило `CLU` в киты, где ему нечего
означать: `CLU = Object.freeze({})` в network и storage, `CLU = WL` алиасом в workloads.

Собственная поверхность кита ВСЕГДА различалась (`WL`, `setCylinderLabel`) - это штатная форма.
Паритетный набор сокращён до четырёх по-настоящему общих имён.

| Кит | Собственная поверхность |
|---|---|
| cluster | `CLU` `LAYOUT` `CLUSTER_TINT` + `P` `F` `defineCard` `POD_VIOLET` `pulsePod` `pulsePodDim` |
| workloads | `WL` `WORKLOADS_TINT` + те же шесть |
| network | `NETWORK_TINT` + те же шесть |
| storage | `setCylinderLabel` `STORAGE_TINT` + те же шесть |

Общий реэкспортный список - **33 имени, одинаковые во всех четырёх**. `NET`/`STO` НЕ выдуманы
заранее: у network четыре разные полосы содержимого (60/1140, 65/1135, 70/1130, 80/1120),
у storage вертикальный стек `STO.L-01`. Грамматику там выведут из реальных карточек при миграции.

**2. Добавлено поле `chipsCued`.** Поле `chips:` пишет через `setVal`; `setChip` делает другое -
`setVal` плюс `.highlight`, если значение ИЗМЕНИЛОСЬ.

> **МОЯ ПОСЫЛКА БЫЛА НЕВЕРНА.** Я написал «networking и storage используют `setChip`».
> Проверено: **cluster 0, workloads 0, network 0, storage 109** (против 7 `setVal`).
> Единственный потребитель - storage, и `storage-pvc-binding.js` смешивает оба на одной
> карточке, то есть глобальный переключатель этого не выразил бы.

Форма - плоское поле-сосед `chipsCued: {}`, а не обёртка значения: обёртка сделала бы значения
`chips` неплоскими данными, и каждый читатель `spec.chips` (спецификация висит на шаге ровно

### 4.2a Миграция ЛОМАЕТ якоря `CARDS.md`, и это надо чинить в том же задании

`unit/docs.test.mjs` тест `A2` требует, чтобы каждый якорь ``### before `<строка кода>` ``
всё ещё встречался в своей карточке. Миграция переписывает карточку, и якорь умирает.

Обнаружено на восьмой карточке: **4 якоря из 124 мертвы**, полный `npm test` красный.
Первые семь не падали только потому, что **ни у одной нет якорей `### before` вообще**.

**Следствие:** к области задания на карточку с якорями добавляется её секция в `<cat>/CARDS.md`.
Перенацелить якорь на эквивалентную строку новой карточки, **текст заметки не трогая**.
Правило «якорь это ДАННЫЕ, не переформулировать» касается случая, когда код не менялся;
здесь код переписан намеренно, и перенацеливание - та же операция, что переименование
заголовка при переименовании карточки.

Перед началом карточки проверять: `grep -c '^### before' <cat>/CARDS.md` в её секции.
Есть якоря - они в области задания.

**Почему пар две.** `oracle:card:diff` покрывает только анимированный путь. Доказано мутацией:
правдоподобное «упрощение» тернарника в `flowLights`
(`e.verb === 'light' ? e.p.targets : e.p.lights` → `e.p.lights`) оставляет анимированные дампы
**побайтово теми же**, а reduced-половина краснеет на двух шагах. `oracle:card:diff` теперь
печатает об этом предупреждение после `CARD CLEAN`.

### 4.3 Правило «сначала воспроизвести, потом чинить»

Миграция обязана воспроизвести существующее поведение, **включая нарушения правил**.
Найденный пример: `cluster-scheduler-decision` не пишет `v1`/`v2` в шаге `score`
и все четыре вердикта в `bind` и `placed` - **10 пропущенных записей**, нарушение `P-01`.

Починка тут **не меняет картинку**: сейчас чипы показывают значения, унаследованные
с предыдущего шага, и это верное изображение. Явная запись тех же значений даёт тот же кадр.
Поэтому она ложится в миграцию полем `chips:` и проверяется тем, что оракул остаётся чистым.

Всё, что картинку МЕНЯЕТ, идёт отдельным коммитом с просмотренным непустым дифом.

## III.3 `document.fonts.check()` не способен сработать

Я предписал его как страж загрузки настоящего шрифта. Проверено на странице без единого

```
check("JetBrains Mono")            -> true
check("Totally Nonexistent 12345") -> true
зарегистрировано @font-face        -> 0
```

При недоступном `fonts.googleapis.com` таблица не подключается, правил `@font-face` нет вовсе,
и `check()` трактует семейство без них как системный шрифт.

Заменено поведенческой пробой ширины (`fallbackFaces()` в фикстуре): нужное семейство
с реальным generic против заведомо невозможного с тем же generic.

поэтому проверка полноты его пропускает. `oracle:diff` обязан отказываться сравнивать дампы
СТАРШЕ базлайна (сравнить mtime), иначе он подтверждает чистоту прогона, которого не было.

Лечение на месте: `pkill`, затем запуск через `setsid ... < /dev/null &`, иначе процесс умирает
вместе с сессией агента. Перед доверием любому зелёному прогону смотреть на ЧИСЛО тестов.

## III.6c Комментарии в коде: предел две строки, и он держится дисциплиной

`S-34` ставит предел в две строки. Разнесение `INTERNALS.md` на этапе 6 его массово нарушило:

## III.7 Смена роли между категориями не может дать SPREAD

`css/styles.css` внутри тонированного диалога переназначает `--cluster-color`,

## IV.5 Ловушки. Каждая стоила времени один раз

**Инструменты**

1. **`npm test -- --test-name-pattern` НЕ фильтрует.** `npm run x -- флаг` дописывает флаг ПОСЛЕ
   позиционных аргументов, node его не разбирает: прогоняются все 1002 теста, пропущено 0.
   Флаг обязан идти ПЕРЕД глобами, вызывать `node --test` напрямую.
2. **Оракул не видит `duration` шага**, а также `id` и `narration`. Правка `1500` → `1501` даёт
   `CARD CLEAN` на всех трёх половинах. Сверять отдельно.
3. **`document.fonts.check()` не способен сработать**: возвращает `true` для заведомо
   несуществующего семейства на странице без единого `@font-face`. Годится только поведенческая
   проба ширины, она есть в фикстуре как `fallbackFaces()`.
4. **Съёмка кадров гоняется с CSS-переходом 0.3s.** На шагах с нулевым размахом переход застревает
   и даёт до **60 551 пикселя** расхождения **на неизменённом дереве**. Лечится пере-входом на
   свежей странице. **Всегда снимать контрольный шум** двумя прогонами одного дерева и называть
   его числом: без него отличить гонку от регрессии нечем.
5. **Приостановленная анимация не вызывает `onfinish`.** Замороженный кадр показывает НАЧАЛО шага
   для любого `F.set` с ненулевой задержкой - самого частого глагола. Анимации свойства (fade)
   при этом видны. Не принимать это за дефект карточки.
6. **Дать элементу ref - значит переименовать его в reduced-дампе** (`slots[3]` → `slot3`).
   Читается как диф, не будучи изменением. Смотреть на счётчики и DOM, а не на дайджест.
7. **Контейнер на `:8080` отдаёт снапшот.** Всегда `BASE=http://localhost:8888`.

**Слой**

8. **Порядок создания анимаций наблюдаем** (R1). `F.set` обязан стоять в `flow` там же, где стоял
   старый `at()`, а не рядом со своим пакетом. Сворачивание `F.light` в `lights:` соседнего хопа
   меняет порядок: на одной карточке это дало 38 изменённых строк.
9. **`reset.pods` копировать ДОСЛОВНО, никогда не выводить** (R5): автовывод добавит
   `clearPodHighlight`, сбрасывающий четыре inline-стиля.
10. **Роль по умолчанию** может дописать `data-role` туда, где его не было (R6), **а палитра этого
    НЕ поймает**: `css/styles.css` схлопывает все четыре категорийных цвета в один тинт внутри
    тонированного диалога. Ловят переписи элементов и комбинаций.
11. **Подпись, которая не является проводом, - это `P.tag`, а не `P.wire`.** `reduced-dump` печатает
    `refs.wires` по ключам, и лишние ключи в этом ведре краснеют, тогда как анимированная половина
    остаётся чистой.
12. **`chips` - состояние ПОСЛЕ статического блока, а не конец шага.** `rewind` - начало на
    анимированном пути, `F.set` может увести значение дальше. Разрешать ключ как
    `chips` → `enter` → `rewind` → все `F.set` в порядке flow.
13. **`reducedLit` - не исключение, а форма**: reduced-путь подставляет подсветку ВМЕСТО движения,
    которого не показывает. Ожидать её везде, где анимированный путь пульсирует, а статический
    обязан что-то сказать взамен.
14. **Локальное имя может затенить китовое.** На cluster карточный `const shade` с другим смыслом
    затенил бы китовый. Перед миграцией `grep` по именам из кита.

**Процесс**

15. **Миграция ломает якоря `CARDS.md`**, а фильтрованный прогон этого НЕ видит по построению.
    Перенацеливать в том же задании. Проверять для каждого: новая строка уникальна в `scheme/js`,
    и старый якорь **не принадлежит заодно другой карточке** - такой случай был.

## IV.7 Форма, которая сработала везде

**Карточный хелпер, ВОЗВРАЩАЮЩИЙ объект полей**, а не пишущий императивно:

```js
const rowState = (spec) => ({ labels: {...}, sublabels: {...}, opacity: {...} });
// в шаге:  ...rowState(SPEC_FOR_THIS_STEP),
```

Она сохраняет `A-16` (непрозрачность блока и его полос задаётся в ОДНОМ месте), перестав быть
императивом. Так легли `setRows`/`setLegacy`, `setBudget`/`setList`, `stage()`, `shades()` -
везде, где план предсказывал `enter`.

**Оправданные escape-хуки, все узкие:**

| Хук | Когда |
|---|---|
| `P.raw` | голый `<rect>`, произвольный глиф, `chip()` из primitives (не `valChip`) |
| `enter` | SVG-**АТРИБУТ** (`width`, `x`) - их не пишет ни одно поле |
| `tune` | захват вложенного элемента, которого не отдаёт часть |
| `F.run` | штатный глагол, не escape: императивный такт ВНУТРИ порядка flow |

## V.3 Фальсификация: три случая, где проверка НЕ падает, и это надо знать

- **R10 с зубами.** На `daemonset` перестановка двух ранговых литералов оставляет **обе** половины
  оракула зелёными: `anim-dump` семплит 7 точек, `dom-dump` читает t=0 и t=span, конечные значения
  чипов совпадают. Поймали только кадры (два Pod материализовались, счётчик читает 1).
  **Но:** перенацелить `at:` на другой хоп анимированная половина ЛОВИТ, потому что `at()`
  регистрирует однумиллисекундную пустую анимацию, и её `delayMs` пишется в дамп. Разные вещи.
- **R3 наблюдаем не всегда.** Перестановка АРГУМЕНТОВ вызова `chip({...})` не видна: порядок
  атрибутов принадлежит примитиву, а не вызову. Краснеет только перестановка атрибутов на самом
  сыром элементе. Фальсифицировать надо второе, иначе проверка «прошла» ни о чём не говорит.
- **R1 наблюдаем не всегда.** Перестановка двух записей `flow` видна, только если записи различаются
  меткой цели или таймингом: две одинаковые стрелки `anim-dump` именует одинаково и их строки
  неразличимы. Выбирать для фальсификации пару, различимую в дампе.
