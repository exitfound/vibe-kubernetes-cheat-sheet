Рабочий документ. Не отправляется в продакшен: `deploy.yml` и `release.yml` это списки
разрешений, а файл в корне репозитория в них не назван.

## Как этим пользоваться дальше

Работа закончена, документ остаётся как запись решений и как список ловушек, которые уже
сработали. Актуальную перепись всегда даёт `cd scheme/tools && npm run gate`, а состояние
документации `node check-notes.mjs`.

Добавление карточки теперь целиком внутри одной папки: файл в `js/schemes/<cat>/`, запись в её
`cards.js`, постер в её `posters.js`, заметка в `docs/CARDS-<cat>.md`. Контракт категории лежит
рядом и подгружается автоматически.

## Зачем это делалось

`scheme/` вырос до 108 карточек и 38 тысяч строк JS, всё лежало плоско. Чтобы добавить одну
карточку, нужно было править `data.js` (1557 строк), `posters.js` (2084), создать файл в папке из
108 файлов и дописать `docs/CARDS.md` (13021 строка). Ничто не подсказывало, какие из этих строк
относятся к нужной категории.

Цель: сделать папку категории единицей контекста, убрать дублирующийся и мёртвый код, а проектную
документацию превратить в сухую спецификацию. **Жёсткое ограничение: нулевое визуальное
изменение.**

### Метод

Правило, которое делает это безопасным: **строки ``### before `...` `` это данные, а не проза, их
не трогаем никогда.** `check-notes` сверяет их буквальным `src.includes()` по всему исходнику
карточки. Заголовки `## <id>` тоже неприкосновенны.

Второе правило: **тело якорной секции это проза, её переписывать можно, строку заголовка нельзя.**
Правки делались скриптом, который находит секцию по заголовку и заменяет только содержимое
ограждения, а неоднозначный префикс считает ошибкой, а не берёт первое совпадение.

Каждый исторический абзац превращается в ПРАВИЛО, либо в ОГРАНИЧЕНИЕ С ПРИЧИНОЙ, либо удаляется.
Уходят даты, «the author», «review stage 2.4 family X», «second-eyes pass», ссылки на
`SCHEME-2.4-PLAN.md`, обороты «used to» и «turned out».

Образец из `CARDS-workloads.md`:

> **было:** «Review stage 2.4 family B listed the DOWN lane as an arrowhead nobody rides, shown on
> four of the six steps. DECLINED 2026-07-30: on this card the absence of traffic down it IS the
> content...»
>
> **стало:** «The DOWN lane carries no ball on `backoff-named`, `doubling` and `cap`, and that
> absence IS the content: those are the steps where Kubelet is HOLDING THE RESTART OFF...
> **Do not add a down-ball to close an "arrowhead nobody rides" finding.**»

Объём при этом почти не падает (workloads 809 → 815, storage 5602 → 5165), и это нормально: цель
не в строках, а в том, чтобы каждый абзац утверждал правило, а не рассказывал историю. Защиты «не применять повторно» обязаны выжить, иначе
следующий проход повторит отменённую правку.

**Никаких regex-проходов.** В проекте записаны четыре случая, когда массовая правка текста оставила
линтеры зелёными, а смысл сломанным. Читать каждую секцию.

### Приёмка каждой категории

```bash
# множество якорей и секций обязано совпасть с версией из git
git show HEAD:scheme/docs/CARDS-<cat>.md | grep '^### before `' | sort > /tmp/a-before.txt
grep '^### before `' scheme/docs/CARDS-<cat>.md | sort > /tmp/a-after.txt
diff /tmp/a-before.txt /tmp/a-after.txt        # обязан быть пуст
cd scheme/tools && node check-notes.mjs        # 624 anchors, 0 stale, 0 orphan, перепись 21/19/37/31
```

Цели: строк с датами 0, «used to / turned out» 0, «review stage» 0, «family [A-Z]» 0.

**Ловушка, на которой я уже попался:** второуровневый заголовок в преамбуле. Каждый `## ` в этих
файлах это id карточки, и `check-notes` парсит их так. `## How to read this file` дал
`workloads 20 (109 of 108)` и orphan-секцию. Преамбульные заголовки только жирным текстом.

## Что было построено по дороге (и почему это важнее строк)

Шесть защит в гейте, каждая добавлена после того, как соответствующий отказ был воспроизведён, и
каждая проверена поломкой:

| защита | что ловит |
|---|---|
| перепись каталога в `catalog.mjs` | инструмент, обходящий не все карточки |
| `R-modulepath`, обе стороны | id не начинается с категории; ничейный `.js` в папке |
| запрет поля `module` | воскресший `data.js` из «до конвенции» |
| `R-poster` | потерянный постер (`renderPoster` молча подставляет заглушку) |
| обход `dashTargets` вместо списка | файл, переехавший из зоны проверки на тире |
| sentinel `_complete` у оракула | оборванный прогон, отчитавшийся «без изменений» |

**Три отказа, которые эти защиты воспроизвели на реальном дереве:**

1. После переноса папок **пять из шести файловых проверок отчитались `0 cards ... OK` с exit 0.**
   Если бы этап 1 не шёл первым, перенос прошёл бы под зелёным гейтом, не прочитавшим ни строки.
2. Вынос `setChip` без правки `prose.mjs` уронил покрытие непрямых строк **с 321 до 114** при нуле
   находок и exit 0. Критерий приёмки того этапа — число 321, а не «0 findings».
3. Оракул отчитался «без изменений» по файлам прошлого прогона, пропустив **11 сломанных
   карточек**: каталоги не очищались, а `anim-dump` умер по таймауту на первой же сломанной.

Полное описание каждого — в сообщениях соответствующих коммитов.

### Ошибки, которые стоит не повторять

- **`git checkout -- <file>` во время незакоммиченной работы.** Восстанавливает из ИНДЕКСА и
  сносит незастейдженные этапы. Снёс правки `data.js` двух этапов, и все 13 проверок остались
  зелёными, потому что удалённое поле уже никто не читал. Для тестов только `cp`-бэкап.
- **Codemod по именам без проверки на самозатенение.** `pod(` → `podShell(` дало
  `const podShell = podShell({...})` в 11 карточках. `node --check` это пропускает: ошибка
  рантаймовая, не синтаксическая.
- **Перечисление вместо обхода.** Список файлов в `dashTargets` пришлось бы править третий раз
  подряд; обход подхватил новые файлы сам.
