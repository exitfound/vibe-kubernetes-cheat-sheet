## workloads-force-deletion

### layout

```
WHAT     The Pod object and the running container are kept equal by the Kubelet acknowledgement
         alone, so a force delete that completes the record without it gives one identity two
         writers.
DEVIATES L-23: 16 of label band, not 34, and the 12 of floor. A 34 band over the 106 Pod is a 152
         frame whose ACK bus, 15 above it, crosses the chips ending at 460, or the frame ends at
         642, past the canvas.
         WL.L-07: the write leaves the API at 828 and jogs to 600 at 145. A centred API would put
         kubectl at 192, left of the L-03 line at 420.
         T-21: `stuck`, `split` and the `recreate` wire name the StatefulSet as the actor, and it is
         drawn only as the owner in the slot caption. The card is about the record and the running
         copy, not the controller that refills the slot. The node controller is drawn by no part
         and named by no step.
CONTENT  Sources (v1.36): Pod Lifecycle, Force Delete StatefulSet Pods, Node Status, Taints and
         Tolerations, release-1.36 podgc, tainteviction and kubectl delete.
         `status.phase stays Running` holds on `stuck`: no podgc path opens while the Node exists,
         NotReady, untainted. `Unknown` is ruled out as a chip value (the task page mixes display
         with phase). The Pod is web-0, its StatefulSet name. Deleting the Node object is safe only
         for a Node confirmed dead. Nodes page says API-initiated eviction, the 1.36 code sends a
         plain DELETE: the card says delete.
OPEN     CENTRE on the chip column (60..540 against 600): a LAYOUT.B column, and a bottom strip
         cannot hold these four values two across (WL.L-05).
```
