## Что здесь есть

| Категория | Разделы |
|---|---|
| **Installation** | Kubeadm, k3s, k3d, KinD, Minikube |
| **Cluster** | Cluster Health, Nodes, Custom Resources, Contexts |
| **Workloads** | Pods, Deployments, StatefulSets, DaemonSets, Services, ConfigMaps & Secrets, Jobs & CronJobs, Volumes, Networking, RBAC, Namespaces |
| **Helm** | Releases, Charts |
| **Kustomize** | Manage, Edit |
| **K9s** | CLI & Launch, UI Shortcuts |
| **Debug K8s** | Installation, Cluster, Network, Storage, Resources, Scheduling |
| **Debug Tools** | Helm, Kustomize, K9s |

У каждого раздела есть своя статическая страница, например [kube.how/cli/section/pod/](https://kube.how/cli/section/pod/), а полный список лежит на [kube.how/cli/section/](https://kube.how/cli/section/). Команды Helm, Kustomize и K9s разбросаны по нескольким разделам, поэтому у каждого из этих инструментов есть ещё и общая страница.

## Как пользоваться

- **Кликните по команде**, и она скопируется в буфер обмена.
- **Отметьте команду звёздочкой** слева от кнопки копирования, и она попадёт в вид Starred (справа вверху в навигации). Звёздочки хранятся только в вашем браузере и никуда со страницы не уходят.
- **Поиск** идёт сразу по всем командам и описаниям и работает в том числе внутри Starred.
- **Новые команды**, появившиеся с вашего прошлого визита, помечены значком `NEW`, пока вы их не скопируете, а у каждого раздела видно, сколько в нём новых.
- **Кнопки рядом с названием раздела** копируют ссылку на раздел, открывают его официальную документацию или создают заранее заполненный issue на GitHub, если вы нашли неверный флаг или устаревшую команду.
- **Навигация** устроена так. Верхний ряд переключает группы, а ряды под ним сужают выбор до категории и раздела.
- **Ссылки на вид**. Адрес меняется вместе с тем, что открыто, поэтому `kube.how/cli/#helm` или `kube.how/cli/#starred` откроют ровно этот вид.
- **Сохранение в PDF**. Кнопка PDF в шапке собирает все команды в книгу, готовую к печати.
- **Английский или русский**. Кнопка языка в правом конце шапки переключает описания и интерфейс. Сами команды остаются такими, как их набирают, а с включённым русским поиск находит совпадения на обоих языках.

### Клавиатура

| Клавиша | Действие |
|---|---|
| `/` | Перейти к поиску |
| `Esc` | Очистить поиск |
| `?` | Показать все сочетания клавиш |

Сочетания работают и в нелатинской раскладке.

## Как это устроено

`/cli/` состоит из одной HTML-страницы и нескольких ES-модулей, шага сборки нет. Здесь же живёт общее оформление, которое используют все страницы сайта.

```
cli/
  index.html          страница
  js/app.js           выводит разделы, поиск, звёздочки, ссылки на вид и PDF-книгу
  js/data.js          все команды, единственный файл, который правят ради содержания
  js/contacts.js      кнопки GitHub, Contacts и Sponsor (файл можно удалить, и кнопки пропадут)
  js/lang/ru.js       русские описания, загружаются только при включённом русском
  js/lib/commands.js  подсветка синтаксиса и порядок команд внутри группы
  js/lib/chrome.js    общая шапка, выпадающие меню и выравнивание логотипа для всех страниц
  js/lib/sidebar.js   общая левая боковая панель
  js/lib/keys.js      общий список сочетаний клавиш
  js/lib/fresh.js     общие значки «новое с прошлого визита»
  js/lib/lang.js      общий переключатель EN / RU
  css/chrome.css      стили общего оформления, каждая страница подключает их перед своими
  css/styles.css      токены и само приложение «Команды»
  css/page.css        статические страницы разделов
  section/            сгенерированные статические страницы разделов (результат сборки, в git не лежат)
```

### Данные

`js/data.js` экспортирует один массив `SECTIONS`. Раздел указывает свою категорию в поле `sub` и содержит группы команд.

```js
{
  id: 'install-kubeadm', title: 'Kubeadm', icon: ICONS.kubeadm,
  sub: 'Installation', version: 'k8s 1.36',
  docs: 'https://kubernetes.io/docs/reference/setup-tools/kubeadm/',
  groups: [
    {
      title: 'Manage',
      desc: 'Initialize the control plane, join worker nodes, ...',
      cmds: [
        { cmd: 'kubeadm upgrade plan', desc: 'Check which versions are available to upgrade to' },
      ],
    },
  ],
},
```

Подсветка красит первое слово как инструмент, второе как действие, дальше флаги, `<заполнители>`, ресурсы и значения, так что разметка в команде не нужна.

## Как добавить команду

1. Добавьте запись `{ cmd, desc }` в нужную группу в `js/data.js`. Порядок внутри массива не важен, при выводе команды сортируются.
2. Пишите заполнители в угловых скобках (`<name>`, `<namespace>`), чтобы было видно, что их нужно подставить.
3. Обновите статические страницы и запустите тесты.

```bash
node tools/pages/build.mjs
cd diagrams/test && npm ci && npm run test:unit
```

Если изменилось общее число команд, `npm run docs:sync` в `diagrams/test` обновит цифры в главном README.

Переименовываете существующую команду? Звёздочки привязаны к точной строке, поэтому добавьте старую строку в `STAR_RENAMES` в `js/app.js` вместе с новой, и сохранённые звёздочки перейдут на неё.

Новый раздел добавляется новым объектом в `SECTIONS`. Ему нужны уникальный `id`, поле `sub` с категорией, `version`, с которой его сверяли, и ссылка `docs`. Его `id` нужно добавить и в подходящий массив `CATEGORIES` в `js/app.js`, от этого зависит место раздела в навигации. Генератор страниц сам создаст для него страницу `/cli/section/<id>/`.
