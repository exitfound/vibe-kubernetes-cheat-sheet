# CLAUDE.md

Guidance for Claude Code in this repository.

## What this repo is

One static, dependency-free site at `kube.how`: three path-based sub-apps sharing visual chrome.

| Path | Sub-app | What it is | Docs |
|---|---|---|---|
| `/` | **Hub** | one-viewport landing page: two entry panels over an aurora and a canvas packet graph | the Hub section below |
| `/cli/` | **Commands** | searchable `kubectl` / Helm / Kustomize / K9s cheat sheet, copy and star | `cli/CLAUDE.md` |
| `/diagrams/` | **Diagrams** | grid of animated SVG Kubernetes diagrams played in a `<dialog>` | `diagrams/CLAUDE.md`, `diagrams/CANON.md` (rules, on demand), `diagrams/js/diagrams/<cat>/CARDS/<id>.md` |

Each sub-app's `CLAUDE.md` is auto-loaded inside its folder. This file covers the repo shape,
running, shipping, the shared chrome and the working discipline.

No framework, no bundler, no npm at runtime: plain HTML, CSS and ES modules. The only external
dependency is Google Fonts (Space Grotesk, JetBrains Mono) via `preconnect` + `preload`. A new
top-level directory is invisible to both shipping workflows (they copy named paths), so it would
reach the container through `COPY . .` and 404 in production. `diagrams/test/` is a dev-only harness.

`README.md` is the user-facing description on GitHub, never shipped. Its headline counts are
checked by `diagrams/test/fixtures/census.mjs` (`npm run test:unit` fails on drift, `npm run
docs:sync` rewrites them). Its per-category tables are checked by nothing: re-read them when a card
or a command block is added or removed.

**Static pages for search engines.** Both apps route by `#`, which crawlers ignore, so
`tools/pages/build.mjs` writes one page per diagram card (`diagrams/card/<id>/`, the card's diagram
beside it as `<id>.svg`), one per command section (`cli/section/<id>/`), one per tool whose commands
span several sections (`cli/section/helm/`, `kustomize/`, `k9s/`), an index of each, `sitemap.xml`
and `llms.txt`. The sitemap gives every page a `<lastmod>` and no `changefreq` or `priority`. All of
it is generated from the same modules the apps load, never edited by hand (the pages carry a
`generated by` marker), and gitignored build output: the workflows build it, and a local `docker
build` needs a generator run first (the Dockerfile refuses without the pages). The same run writes
two files that ARE committed: `diagrams/js/revisions.js`, because `app.js` imports it, and
`tools/pages/dates.json`, the day each page last changed, which the `<lastmod>` values come from.
`build.mjs --check` fails while either is stale, `npm test` reruns the generator first (it also
deletes pages whose card is gone).

## Running

```bash
python3 -m http.server 8888 --bind 0.0.0.0
```

Open `/`, `/cli/` or `/diagrams/`. Serve from the repo root: links between pages are root-absolute.
After touching the chrome, run `node tools/smoke/site.mjs` (drives every key, button and view in a
real browser, Playwright from `diagrams/test`, `npm ci` there once).

Docker (nginx, the whole tree):
```bash
docker rm -f kube-cheatsheet && docker build -t kube-cheatsheet . && docker run -d --name kube-cheatsheet -p 8080:80 kube-cheatsheet
```
`configs/nginx.conf` sets gzip, security headers, `no-cache` for local iteration, and
`error_page 404` to `404.html`.

## Deployment

Every push to `main` ships immediately, no staging. Hosting is GitHub Pages, DNS on Cloudflare:
responses come straight from GitHub Pages, with no Cloudflare proxy or cache in front.

- `verify.yml` is the gate both publishing workflows call first, and it runs on its own on every push
  to a branch other than `main` (or by hand). Five jobs: actionlint over the workflows; `build.mjs
  --check`, a page build and the unit tests; the staged and stamped site (exactly what deploy ships)
  checked for leaked internal files and driven by `tools/smoke/site.mjs _site`; the browser gate
  (`npm test`: unit plus render over one walk, against a local server); and the Docker image built,
  run and probed (pages 200, internal docs 404). Playwright is pinned in `diagrams/test/package-lock.json`.
- `deploy.yml` builds the static pages, stages them with `tools/deploy/stage.sh` (the allowlist:
  `index.html`, `404.html`, `favicon.svg`, `favicon.ico`, `robots.txt`, `sitemap.xml`, `llms.txt`,
  `CNAME` and the `images/`, `cli/`, `diagrams/` directories, minus the internal docs), stamps every
  local module, script and stylesheet URL with `?v=<sha>` (`tools/deploy/version.mjs`) and publishes.
  A newer push waits for a running deploy instead of cancelling it.
- `release.yml` builds the static pages and zips the shippable tree (plus `Dockerfile`, `configs/`,
  `.dockerignore`) into a Release `vYYYY.MM.DD-<sha>`. Its `paths:` trigger matches that list, so
  docs-only commits skip it.
- `tools/` never ships, but the workflows run its scripts: `tools/pages/build.mjs`,
  `tools/deploy/stage.sh`, `tools/deploy/version.mjs` and `tools/smoke/site.mjs`. Do not move them
  without updating the workflows.
- A computed `import()` path is the one URL the stamp cannot rewrite, so it appends the module's own
  stamp (`ASSET_V` in `diagrams/js/app.js`). `version.mjs` fails the deploy on any local URL it missed.

**Internal docs never reach production.** They are excluded by NAME: `CLAUDE.md`, `CARDS.md`,
`CANON.md` anywhere, every `CARDS/` folder, and `diagrams/test/`. Three mechanisms must agree:
`tools/deploy/stage.sh` and `release.yml` are allowlists, `.dockerignore` is a denylist, so a new internal file
inside a shipped directory must be named in all three (`unit/files.test.mjs` S-41 checks it). The
container (`COPY . .`) is the cheapest place to catch a miss: `curl -s -o /dev/null -w
'%{http_code}' http://localhost:8080/<path>` must return 404.

`404.html` is the custom not-found page (a small Tetris game under the shared header and sidebar).
It links `/cli/css/chrome.css` and `/cli/css/styles.css` and imports the shared chrome modules from
`/cli/js/lib/`, like every other page.

## Shared chrome (all three pages)

**Sidebar.** A fixed 38px left sidebar with Home (`#sideHome`), Commands (`#sideCli`) and Diagrams
(`#sideDiagram`). The current page's button ships `.active` + `aria-current="page"` in its HTML. A
bottom `.side-toggle` collapses it (`body.sidebar-collapsed`), a `.side-expand` tab restores it.
The choice persists in `localStorage` `kube-how:sidebar-collapsed:v1`: `'1'` hidden, `'0'` shown,
absent means shown on desktop and hidden at <=680px. Wiring: `cli/js/lib/sidebar.js`, the one copy,
imported by every page. On `/cli/` and `/diagrams/` a `#sideKeys` button opens the shortcuts sheet
(hidden on touch).

**Shortcuts sheet.** `?` (or `#sideKeys`) opens `<dialog class="keys-dialog">`, built by
`setupKeysHelp(groups)` in `cli/js/lib/keys.js`, which `/diagrams/` imports too. Change a key
binding and its row in the same edit. Every character shortcut goes through `isSlash`, `isQuestion`
or `isLetter`, which match the typed character first and fall back to the physical key on a
non-Latin layout (so `/`, `?`, `F`, `R`, `L` work on a Russian layout). Never match those on `e.key`
alone. Both search fields carry a `<kbd class="search-kbd">/</kbd>` hint.

**New since your last visit.** `cli/js/lib/fresh.js` (imported by both apps) keeps a
per-browser map of seen items (`kube-how:cli-seen:v1` by `hashKey(rawCommand)`,
`kube-how:diagram-seen:v1` by card id). The first visit records a baseline that is never new. An item
that appears later reads `NEW` for `FRESH_DAYS` (14) until copied or opened. No dates live in the
content data.

**Analytics.** The Cloudflare Web Analytics beacon ends every page except `404.html`. On `/cli/` and
`/diagrams/` it carries `"spa": false`: SPA mode counted every `replaceState` (each step, flip and
filter) as a page view of the bare path. Card and section views come from the static pages. Both
apps write their URL with the trailing slash. `tools/smoke/site.mjs` guards both.

**Accessibility baseline** (axe-core 0 violations, Lighthouse a11y 100). Exactly one `h1` per page
(a `.sr-only` line inside `<header>` on the three apps), the logo link named by its visible text
(`404.html` uses `aria-label`), every icon-only button labelled, a gap between the 44px star and copy
buttons on touch. Re-check with axe-core after any chrome change.

**Social previews.** `images/og-hub.jpg`, `images/og-cli.jpg` (`/cli/`), `images/og-diagrams.jpg`,
1200x630, raster with no source in the repo: any text painted into one has to be true.
`images/apple-touch-icon.png` is the home-screen icon every page links.

**Header.** GitHub / Contacts / Sponsor on all three pages, no cross-navigation (that is the
sidebar's job). The data is `cli/js/contacts.js`, the rendering, the dropdowns and the wallet copy
are `setupHeader()` in `cli/js/lib/chrome.js`. Deleting `contacts.js` drops the buttons everywhere.

**Chrome parity.** The chrome has one copy, shared by every page including the generated static
ones: `cli/css/chrome.css` (sidebar, header, search, shortcuts sheet, scroll-to-top, footer,
scrollbar), linked BEFORE the page's own stylesheet, and `cli/js/lib/` (`chrome.js`, `sidebar.js`,
`keys.js`, `fresh.js`). The app stylesheets supply the tokens and only app-specific overrides.
Each page calls `alignLogo(selector)` from `chrome.js`, which centres the logo icon over the nav's
"All" button (the hub and `404.html` measure an invisible ghost nav), skipped at <=900px. The
scrollbar rules live in `chrome.css`, so every page has the same width and the centred content
does not drift on tab switch.

**First paint.** Every `<head>` starts with `color-scheme: dark` hints and an inline
`background:#110f1f;color:#ece9ff`, and `cli/js/app.js` awaits one painted frame before building
the command list. Do not reorder or remove these.

**Writing rules.** No em-dashes or en-dashes anywhere. No semicolons in user-visible prose. No
apostrophes in `diagrams/` narration and wire strings (they are single-quoted JS).

**The write hook.** `.claude/hooks/check-js.sh` runs after any Edit or Write to `diagrams/js/**/*.js`,
parses the file as an ES module (`node --input-type=module --check`, file on stdin) and exits 2 if it
no longer parses, which is almost always an apostrophe inside a narration string.

## Working discipline

- **Scope.** Make only the change asked for. Do not recolour, re-trim or "improve" neighbours. When
  matching a sibling, match it exactly. If the change seems to need more, stop and say so.
- **File safety.** Never overwrite or delete an untracked or user-authored file. Check `git status`
  before writing to a path that may exist.
- **`.codegraph/` is never deleted** (the CodeGraph index, gitignored, never shipped). It is never
  part of a revert, a tidy-up or a `git clean`.
- **Look at what you changed.** A green suite is not a looked-at page. For any visual or animation
  change open the rendered frames of every item you touched, not a sample, after fonts load. When a
  rule can only be satisfied by making the picture worse, leave the finding open and say why.
- **Read after a mass edit.** After a regex sweep or codemod over prose, read the result: the
  linters stay green while the meaning breaks.
- **Technical text gets a second reader**, and the cheapest check is internal contradiction: a card
  disagreeing with its own steps, labels, aria-label or a sibling.
- **Posters need concept sign-off** in one line before rendering (CANON `R-`).
- **Counts.** `npm run docs:sync` in `diagrams/test` after adding or removing cards or commands.
  Documents state no other counts.
- **Commits.** After an approved, green unit of work, offer to commit. Never commit unasked.

# `/` Landing hub (`index.html`)

One file: hub CSS and JS are inline, and only `/cli/css/chrome.css`, `/cli/css/styles.css`,
`/cli/js/lib/sidebar.js` and `/cli/js/lib/chrome.js` (which loads `/cli/js/contacts.js` lazily) come
from cli, plus the two catalogs and `/cli/js/lib/fresh.js` lazily after paint for the live counts.

- Two `<a class="hub-panel">` cards (Commands, Diagrams) over a drifting three-blob aurora (hand-tuned
  trajectories) and a canvas node graph with packets on soft links. The radial-gradient and
  rich-landing concepts were rejected. A "Continue: <last diagram>" link was rejected too.
- An inline script rewrites legacy hashes: `#diagram=...` (and its old name `#scheme=...`) and
  `#at=...` go to `/diagrams/`, any other hash to `/cli/#hash`. That is why `/diagrams/` names its
  filter key (`#at=`).
- Each panel's `.hub-stat` line shows live counts plus an `N new` pill, filled in
  `requestIdleCallback` from `/cli/js/data.js`, `/diagrams/js/data.js` and `/cli/js/lib/fresh.js` (which
  also warms the cache). The line keeps a 20px min-height so nothing jumps.
- Hub-only tokens (`--hub-diagram-*`) live inline.
- At <=900px the three header actions fill the second header row as equal labelled buttons. The
  stacked panels are `flex: 1 0 auto` (with `overflow: hidden` a flex item's minimum height is 0 and
  the CTA got cut). Padding 24px, gap 10px, icon 56px keep the hub one viewport at 390x844 and
  700x900. Shorter phones scroll a little.
