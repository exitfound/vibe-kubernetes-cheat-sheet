kube.how задуман как быстрый справочник для всех, кто каждый день работает с Kubernetes. В нём собраны шпаргалка по командам и библиотека анимированных диаграмм того, как кластер устроен внутри. Регистрация, реклама, cookie и установка не нужны, достаточно открыть страницу. Интерфейс, описания и пояснения к диаграммам есть на русском и на английском, а язык переключается одной кнопкой в шапке.

## Что внутри

Сайт статический и состоит из трёх приложений.

| Путь | Приложение | Что это |
|---|---|---|
| [`/`](https://kube.how/) | **Хаб** | Стартовая страница на один экран. Две панели входа с живыми счётчиками поверх «северного сияния» и графа с бегущими пакетами |
| [`/cli/`](https://kube.how/cli/) | **Команды** | Шпаргалка по kubectl, Helm, Kustomize и K9s с поиском, копированием в один клик и избранным |
| [`/diagrams/`](https://kube.how/diagrams/) | **Диаграммы** | Сетка анимированных SVG-диаграмм. По клику на карточку пошаговая анимация объясняет, как устроен механизм |

Здесь сотни команд, от установки кластера до его отладки, и они охватывают kubectl, kubeadm, k3s, k3d, KinD, Minikube, Helm, Kustomize и K9s. Команда копируется по клику, те, к которым вы возвращаетесь чаще всего, можно отметить звёздочкой, а клавиша `/` сразу ставит курсор в поиск по всему списку. У каждого раздела есть и своя страница, например [kube.how/cli/section/pod/](https://kube.how/cli/section/pod/).

### Диаграммы

Больше сотни анимированных диаграмм о том, как Kubernetes работает изнутри, в четырёх категориях: Cluster, Workloads, Networking и Storage. Каждая карточка открывает окно, где механизм проигрывается по шагам. Панель с пояснением рассказывает, что движется и почему, а рядом стоят ссылки на документацию Kubernetes, по которой собрана диаграмма. У каждой диаграммы есть и отдельная страница для чтения, например [kube.how/diagrams/card/cluster-architecture/](https://kube.how/diagrams/card/cluster-architecture/).

**[Руководство по диаграммам →](./diagrams/README.ru.md)**

## Как это устроено

- **Без фреймворка, без сборщика и без npm в рантайме.** Браузер загружает обычные HTML, CSS и ES-модули напрямую. Из внешних запросов остаются только Google Fonts и счётчик Cloudflare Web Analytics, который обходится без cookie.
- **Диаграммы нарисованы вручную в SVG** и двигаются через Web Animations API внутри нативного `<dialog>`. Никаких библиотек для диаграмм, canvas или WebGL.
- **Статическая страница на каждую карточку и каждый раздел.** Оба приложения хранят состояние после `#`, а поисковики эту часть адреса не читают. Поэтому `tools/pages/build.mjs` собирает по HTML-странице на каждую диаграмму и каждый раздел команд, а также `sitemap.xml` и `llms.txt`, причём из тех же модулей, что загружают сами приложения.
- **Браузер проходит каждый шаг.** Тесты в `diagrams/test/` работают на встроенном тест-раннере Node вместе с Playwright. Unit-тесты проверяют каталог и тексты, а render-тесты проигрывают каждый шаг каждой диаграммы. CI прогоняет их перед каждым деплоем.

## Локальный запуск

Подойдёт любой сервер статических файлов. Раздавать нужно корень репозитория, потому что ссылки между страницами идут от корня. Генератору страниц и тестам нужен Node 22 или новее (в CI стоит Node 24).

```bash
python3 -m http.server 8888 --bind 0.0.0.0
```

Хаб откроется на [localhost:8888](http://localhost:8888), команды на `/cli/`, диаграммы на `/diagrams/`. Статические страницы карточек и разделов собираются отдельно, поэтому если они нужны, один раз запустите `node tools/pages/build.mjs`.

### Docker

Образ раздаёт весь сайт через nginx. Сначала сгенерируйте статические страницы, потому что без них сборка образа не запустится.

```bash
node tools/pages/build.mjs
docker compose up -d --build
```

Сайт откроется на [localhost:8080](http://localhost:8080). После изменений достаточно снова выполнить `docker compose up -d --build`. Без Compose это выглядит так:

```bash
docker build -t kube-cheatsheet .
docker run -d --name kube-cheatsheet -p 8080:80 kube-cheatsheet
```

## Структура репозитория

У каждого приложения есть своё руководство, это [`cli/README.ru.md`](./cli/README.ru.md) и [`diagrams/README.ru.md`](./diagrams/README.ru.md).

```
index.html               стартовая страница, всё в одном файле
404.html                 своя страница «не найдено»
cli/                     приложение «Команды» и общее оформление всех страниц
diagrams/                приложение «Диаграммы», его каталог и тесты
images/                  превью для соцсетей и иконка для домашнего экрана
scheme/                  редирект со старого адреса /scheme/ на /diagrams/
tools/pages/build.mjs    собирает статические страницы, sitemap.xml и llms.txt
tools/deploy/            готовит сайт к GitHub Pages и ставит версию в адреса файлов
tools/smoke/site.mjs     прокликивает в браузере каждую клавишу, кнопку и вид
configs/nginx.conf       конфигурация nginx для Docker-образа
compose.yaml             локальный запуск в Docker
.github/                 workflows, Dependabot и картинки для README (на сайт не попадают)
```

## Как помочь проекту

Нашли неверный флаг, устаревшую команду или диаграмму, которая расходится с документацией? У каждого раздела команд и у каждой диаграммы есть кнопка с флажком, которая открывает заранее заполненный issue на GitHub. Pull request тоже приветствуются.

- **Команды** лежат в одном файле, `cli/js/data.js`. Подробности в разделе [Как добавить команду](./cli/README.ru.md#как-добавить-команду).
- **Диаграммы** лежат в отдельной папке на каждую категорию. Подробности в разделе [Как добавить диаграмму](./diagrams/README.ru.md#как-добавить-диаграмму).
- После правок запустите `node tools/pages/build.mjs`, чтобы обновить статические страницы, а затем тесты командой `cd diagrams/test && npm ci && npm run test:unit`.
